# 快爆收入统计页面组件与 UI 规范

> 版本：v1.0  
> 来源：快爆收入统计第一批「手游 / 充值明细」原型确认结果  
> 用途：后续快爆收入统计页面复用，也可作为同类后台列表页的组件规范参考。

## 0. 最终实施状态

- 本次原型的 7 个二级菜单批次均已完成并经用户确认。
- 已完成页面：手游充值明细（正式订单、测试订单）、手游充值统计（游戏、开发者、汇总）、手游付费下载明细、手游付费下载统计（游戏、开发者、汇总）、手游收入汇总统计（游戏、开发者）、PC 游戏充值明细、快爆小游戏充值明细。
- PC 游戏充值和快爆小游戏充值仍只提供明细查询，不进入快爆现有收入汇总统计。
- 本规范为本次确认后的最终组件与 UI 复用基线；后续新增页面应优先复用本文组件规则，不得据此改变既有业务流程和指标口径。

## 1. 使用范围与原则

- 本规范记录已确认的页面布局和组件交互，不改变业务流程、统计范围或指标口径。
- 快爆页面向 4399 的布局风格靠齐，但业务数据域、统计规则和字段语义仍按快爆现有规则执行。
- 正式订单和测试订单使用相同页面结构与组件，不在测试订单页面增加额外提示；两者数据域仍保持独立。
- 页面新增组件优先复用本规范，不重复设计相同交互。

## 3. 页面整体骨架

页面从左到右、从上到下由以下区域组成：

1. 深色左侧业务菜单。
2. 顶部目录选择与面包屑。
3. 二级功能页签。
4. 查询内容卡片。
5. 顶部查询栏。
6. 数据表格。
7. 居中分页。
8. 按需打开的筛选浮层、时间浮层和下钻 Modal。

### 3.1 左侧菜单

- 菜单不显示图标。
- 一级菜单展示业务分组，二级菜单展示具体功能。
- 当前二级菜单使用主题蓝色背景。
- 尚未绘制的菜单可显示“待绘制”，但不得展示旧页面内容。

### 3.2 顶部区域

- 目录选择器显示 `好游快爆 / 数据中心`。
- 面包屑使用 `一级业务 › 二级菜单` 格式；层级箭头使用约 `17px` 字号并保持垂直居中，使箭头视觉尺寸明显大于正文标点。
- 二级功能页签使用主题蓝色背景和白色文字。
- 二级页签与下方查询内容区之间保留 `12px` 垂直间距。

## 4. 顶部查询栏

### 4.1 排列规则

- 三级功能切换、时间范围、查询输入框和导出按钮全部位于顶部查询栏。
- 从左到右依次排列，导出按钮位于全部条件之后。
- 页面宽度不足时按原顺序自动换行，不显示横向滚动条。
- 普通查询框不在输入框外显示字段名，只使用占位提示。
- 金额查询框不显示浏览器原生的上下步进箭头，但仍按数值输入和校验处理。
- 输入框、下拉选择及自定义切换组件获得焦点或处于选中操作状态时，边框使用平台主题蓝 `#4165D7`，不显示浏览器默认黑色描边。
- 时间范围组件不显示独立的“时间”文字标签，仅显示日历图标和日期范围。

### 4.2 查询行为

- 输入或修改条件后立即刷新列表与查询总计。
- 不设置额外的“查询”按钮。
- 不设置“重置条件”按钮。
- 条件变化后分页自动回到第 1 页。

### 4.3 导出按钮

- 使用主题蓝色主按钮。
- 按钮文字为“导出”。
- 不显示图标。
- 位于查询条件末尾，跟随查询栏自动换行。

## 5. 时间范围选择器

### 5.1 输入框

- 使用项目内指定的日历 SVG 图标，不使用字符图标。
- 日期格式为 `YYYY-MM-DD — YYYY-MM-DD`。
- 控件高度为 `32px`。

### 5.2 日历浮层

- 同时显示连续两个月份。
- 选中日期使用主题蓝色正圆，宽高必须一致，不得显示为椭圆。
- 相邻月份中的补位日期不显示选中态或范围背景，避免同一日期在两个面板重复高亮。
- 选中范围中间日期使用浅蓝色背景连接。
- 单箭头 `<`、`>` 分别切换上一个月、下一个月。
- 双箭头 `«`、`»` 分别切换上一年、下一年。
- 点击组件外的页面区域时自动关闭浮层。
- 完成结束日期选择后自动关闭浮层。

### 5.3 统计页时间精度

统计页时间组件与明细页区分，根据时间精度切换对应面板：

- 按日：左侧提供“昨天、过去7天、过去30天、过去90天”快捷选项，右侧显示双月日期面板。
- 按月：输入框显示 `YYYY-MM — YYYY-MM`，浮层同时显示连续两个年份，每年提供 12 个月份选择。
- 按年：输入框显示 `YYYY — YYYY`，浮层以十年为一个区间展示年份，双箭头切换上一个或下一个十年。
- 月份和年份选择均支持起止范围，起止项使用主题蓝色，范围中间项使用浅蓝背景。
- 切换时间精度只改变时间选择和展示方式，不改变对应统计指标口径。

### 5.4 统计页展示方式

- 折线图入口右侧、时间精度左侧增加展示方式下拉框。
- 选项为“周期明细”和“区间汇总”，默认选择“周期明细”。
- 周期明细：按照当前选择的按日、按月或按年粒度拆分数据。
- 区间汇总：将整个查询时间范围内的数据合并；游戏统计按游戏汇总，开发者统计按开发者汇总，汇总统计合并为一条。
- 区间汇总模式下，列表“时间”列显示当前实际查询区间；按日显示完整日期区间，按月显示年月区间，按年显示年份区间。起止值相同时只显示一个值，不重复显示。
- 待结算金额按“成功金额 + 平台补贴金额”计算；平台补贴占比按“平台补贴金额 ÷ 待结算金额”计算。区间汇总后的金额、券数量和订单次数使用求和结果，占比必须使用汇总后的分子、分母重新计算。
- 游戏统计、开发者统计和汇总统计均支持按日、按月、按年检索；时间选择器、列表时间粒度、周期明细和区间汇总行为保持一致。三个页面列表均包含订单次数、订单人数，两个字段均作为普通数值展示，不提供下钻弹窗。

## 6. 数据表格

### 6.1 通用样式

- 表头使用浅灰背景，文字加粗。
- 金额字段右对齐并保留两位小数，充值明细与充值统计均不显示 `￥` 或其他货币符号。
- ID 与名称组合显示为 `ID / 名称`。
- 玩家查询能力保留 `玩家ID / 名称` 联合匹配。快爆当前玩家 ID 为纯数字，例如 `151668671`，名称字段没有数据，因此玩家列统一显示为 `玩家ID / -`，不得使用带字母的模拟 ID 或模拟名称补齐。
- 普通数据行默认白色，仅在鼠标悬停时显示浅灰背景。
- 数据行之间使用浅色横向边框。
- 页面不得出现整体横向滚动；必要时调整列宽或允许内容合理收缩。

### 6.2 查询总计行

- 当前筛选结果有数据时，查询总计固定为表体第一行。
- 查询总计行背景保持白色。
- 查询总计基于全部筛选条件，不是当前分页数据求和。
- 查询总计行不显示订单数量；总条数仅在分页组件显示。
- 当前筛选结果为 0 时，不显示查询总计行，表格直接显示“暂无数据”。

### 6.3 空值与下钻样式

- 空字段统一显示 `-`。
- 空值 `-` 不显示下划线，不可点击，不打开下钻。
- 只有确实存在下钻信息的字段才显示下划线和手型光标。
- 下钻字段悬停时可切换为主题蓝色。

## 7. 表头筛选组件

### 7.1 入口

- 筛选入口位于对应表头文字右侧。
- 使用实心漏斗图标，不使用文字箭头或三角形代替。
- 点击表头文字或漏斗图标均可打开筛选菜单。

### 7.2 筛选菜单

- 菜单以浮层形式显示在表头下方。
- 选项必须纵向逐行排列，不得被表格布局拉成横向。
- 当前选项使用主题蓝色文字。
- 选择后立即刷新列表并关闭菜单。

## 8. 分页组件

- 分页组件整体水平居中。
- 从左到右依次显示：总条数、每页条数、上一页、连续页码、省略号、末页、下一页。
- 每页条数选项为：`10`、`20`、`30`、`50`、`100`、`200` 条/页。
- 当前页使用主题蓝色边框和文字。
- 不可用的上一页或下一页按钮使用禁用样式。
- 暂无数据时显示 `共 0 条`，页码保持不可越界。

## 9. 下钻弹窗 Modal

### 9.1 外层结构

- 弹窗居中显示，遮罩覆盖当前页面。
- 推荐宽度为 `450px`，窄屏最大宽度为 `90vw`。
- 不显示弹窗标题。
- 不显示底部“关闭”按钮。
- 只在右上角保留 `×` 关闭图标。
- 点击遮罩或右上角关闭图标可关闭弹窗。

### 9.2 信息表格

- 表格固定为“名词 / 说明”两列。
- 一行只显示一个信息项，不得一行放置两个信息项。
- 表头背景为白色，文字居中加粗。
- 内容行使用白色、浅灰色整行交替背景。
- 同一行左右两个单元格必须使用相同背景色。
- 边框使用浅灰色，文字使用中性灰色。
- JSON 或回传值使用等宽字体并格式化为多行展示。

### 9.3 订单详情字段顺序

1. 平台游戏
2. 平台订单号
3. 游戏订单号
4. 游戏区服ID
5. 游戏回传值

字段内容必须来自当前数据行，不得为了页面相似度新增或更改业务字段。

## 10. 正式订单与测试订单

- 使用同一个页面组件和同一套 UI 规范。
- 通过三级功能下拉框切换。
- 页面字段、查询栏、分页、筛选和弹窗结构保持一致。
- 测试订单页面不额外显示提示条。
- 测试订单仍独立查询、独立统计，不进入正式订单汇总和快爆正式收入。

## 10.1 付费下载明细

- 页面归属为“手游 / 付费下载明细”，三级功能仅包含“付费下载明细”。
- 查询栏与手游充值明细保持相同结构和顺序，依次提供时间、订单号、游戏订单号、游戏ID/名称、玩家ID/名称、开发者ID/名称、购买金额、优惠券面额、优惠券ID和导出；输入或修改条件后即时刷新。金额字段使用付费下载业务名称“购买金额”。
- 列表字段为时间、订单号、游戏ID/名称、玩家ID/名称、支付渠道、购买金额、平台补贴金额；玩家名称按快爆现状显示“-”。
- 付费下载明细“支付渠道”表头使用漏斗筛选，选项为：全部、QQ钱包APP、银联微信小程序、银联支付宝小程序、支付宝APP、微信APP、微信扫码、支付宝扫码；选择后即时刷新列表和查询总计，并回到第1页。
- 付费下载明细“支付渠道”筛选表头不得叠加表头与按钮两层内边距；表头文字、漏斗图标、数据内容和筛选下拉层使用同一列左边界。
- 查询总计有数据时固定为表体第一行，仅汇总购买金额和平台补贴金额；无数据时不显示总计行。
- 订单号为普通文本，不增加功能清单未定义的订单号下钻。
- 总计行平台补贴金额可下钻，Modal 字段为优惠券面额、平台补贴金额，数值基于当前全部筛选结果汇总。
- 数据行平台补贴金额可下钻，Modal 字段为平台游戏、订单号、优惠券面额、平台补贴金额、优惠券ID；零值显示“-”且不可点击。
- 默认每页20条，分页组件和 Modal 样式复用充值明细规范；金额不显示货币符号。

## 10.2 付费下载统计

- 页面归属为“手游 / 付费下载统计”，三级功能包含“游戏统计、开发者统计、汇总统计”，结构与充值统计一致，不再单设订单统计。
- 游戏统计列表字段为：时间、游戏ID/名称、开发者ID/名称、公司/个人名称、待结算金额、成功金额、平台补贴金额、平台补贴占比、券使用数、券面额。
- 开发者统计列表字段为：时间、开发者ID/名称、公司/个人名称、待结算金额、成功金额、平台补贴金额、平台补贴占比。
- 游戏统计、开发者统计和汇总统计列表均增加“订单次数、订单人数”两个指标。
- 付费下载统计三个列表的“订单次数”和“订单人数”均支持下钻；查询总计行展示全部筛选结果拆分，数据行展示当前行拆分。“订单次数”弹窗字段为购买订单次数、获赠订单次数；“订单人数”弹窗字段为购买订单人数、获赠订单人数。
- 汇总统计列表字段为：时间、待结算金额、成功金额、平台补贴金额、平台补贴占比、订单次数、订单人数。
- 三个页面均复用统计页的按日、按月、按年时间组件，以及“周期明细 / 区间汇总”、即时查询、查询总计、每页20条分页、导出和 1030px 图表抽屉规范。
- 三个统计页面的周期明细图表指标包含待结算金额、成功金额、订单次数、订单人数，不带入充值统计的失败金额等专属指标。
- 付费下载统计的区间汇总收入柱状图同样不包含失败金额；柱体、图例和悬浮提示中均不得显示失败金额。
- 查询总计基于当前全部筛选结果；无数据时不显示查询总计。金额不显示货币符号。

## 10.3 收入汇总统计

- 页面归属为“手游 / 收入汇总统计”，三级功能只包含游戏统计、开发者统计。
- 游戏统计字段为时间、游戏ID/名称、充值待结算金额、付费下载待结算金额、总收入；开发者统计增加开发者ID/名称、公司/个人名称。
- 总收入严格保持快爆现有口径：充值成功订单收入 + 付费下载参与结算金额；不包含测试订单、小游戏充值、PC游戏充值和广告收入。
- 图表指标仅为总收入。周期明细展示总收入趋势折线；多个对象按查询区间总收入降序选择 Top15，默认显示 Top5。区间汇总展示按总收入降序选择的 Top15 柱状图。
- 收入汇总统计抽屉使用专属三行灰色说明：周期明细展示“总收入”时间趋势，多个对象默认显示 Top5 并可选择 Top15；区间汇总展示“总收入”柱状图，多个对象展示 Top15；两种模式均按统计对象在完整查询时间区间内的总收入汇总值降序选取 Top15。不得复用充值统计中的“收入／订单数”“待结算金额”说明。
- 页面复用统计页按日、按月、按年，周期明细／区间汇总、查询总计、每页20条分页、导出和 1030px 图表抽屉规范；金额不显示货币符号。

## 11. 图表抽屉

- 点击查询栏中三级功能右侧的图表图标按钮，从页面右侧打开 Drawer。
- 图表入口使用无外框的深色折线图标，图标区域仅在右侧显示一条浅灰色竖分隔线，不使用圆角方形按钮样式。
- Drawer 固定宽度为 `1030px`，小于可用视口时使用 `max-width: 90vw`。
- 标题栏固定显示“统计图”和右上角关闭按钮。
- 图表内容区独立纵向滚动，不带动背景页面。
- 周期明细使用时间趋势折线图：单对象显示一条折线，多对象按当前指标选出查询区间 Top15，默认显示前 5 条折线并允许通过图例选择其余对象。汇总统计周期明细显示整体时间趋势。
- 游戏统计和开发者统计选择区间汇总时，汇总整个查询时间区间并展示 Top15 对象分层柱状图；汇总统计显示整体单柱。柱状图右上角支持“收入／订单数”维度切换：“收入”包含待结算金额、成功金额、失败金额，以待结算金额为整柱基准；“订单数”包含订单次数、订单人数，以订单次数为整柱基准。其他指标按与基准指标的实际比例从同一基线分层显示，不累加为柱高。各指标层横向使用相同完整柱宽。
- 多对象 Top15 折线图的图例列出全部 Top15 对象，初始仅选中并显示排名前 5 的折线；第 6～15 名默认隐藏，用户点击对应图例后显示，再次点击可隐藏。Top15 排名随当前图表指标变化重新计算。
- 折线图底部不重复显示当前指标图例；当前指标由右上角指标选择器表达，图表区域仅保留对象选择图例。
- 折线图横轴必须覆盖所选统计区间内完整的年／月／日序列；某对象在某个时间点没有统计数据时，该图表数据点按 `0` 显示。该补零规则仅用于统计图连续时间轴展示，不得在列表中伪造业务明细记录。
- 折线图按时间区域响应悬浮，不要求精准移到数据点。竖线定位到某个日期／月份／年份时，浮层标题显示该时间，并一次列出当前所有已选中折线对象在该时间的当前指标数值；每条信息使用与折线一致的颜色标识。无数据对象显示 `0` 或 `0.00`，移出图表后关闭浮层。
- 折线图悬浮数据浮层固定显示在绘图区最上方，不因已选对象数量或悬浮日期改变纵向位置；横向位置仍跟随当前日期并避免超出绘图区。
- 悬浮浮层对象不超过 8 个时使用单列，超过 8 个时自动改为两列，从而将浮层高度控制在绘图区内部，不得遮挡横轴日期或底部对象图例。
- 折线数据点使用小号空心圆，半径 `2px`、描边约 `1.4px`；折线宽度为 `2px`，避免多折线场景下圆点和线条互相遮挡。悬浮仍由日期区域触发，不依赖圆点尺寸。
- 原型 Mock 数据至少覆盖 15 个游戏、对应开发者及多个跨月时间点；默认查询区间内应具备连续的每日数据。不同游戏必须模拟明显不同的走势类型，包括增长、下降、先升后降、先降后升、周期波动、稳定、双峰和末期突增等，不得仅通过同比例缩放形成平行折线。金额与订单仍需满足已确认计算关系。
- 充值统计列表默认每页显示 20 条数据，分页必须切换实际列表数据；查询总计基于全部筛选结果且固定为表体第一行，不计入每页 20 条额度。
- 充值统计周期明细列表默认按时间倒序排列，最新日期／月份／年份优先；同一时间下保持对象的稳定顺序。查询总计固定为第一行且不参与排序。区间汇总记录显示统一的实际查询区间，并保持对象顺序。
- 趋势折线图只有一个时间数据点时，数据点及对应时间标签在绘图区水平居中显示；存在多个数据点时按时间顺序均匀铺开。
- 图表抽屉顶部统一显示三行灰色小号说明：第一行“「周期明细」展示时间趋势折线，多个统计对象默认显示 Top5，并可选择 Top15。”第二行“「区间汇总」可按“收入”或“订单数”维度查看分层柱状图；多个统计对象展示 Top15。”第三行“Top15 选择逻辑：「周期明细」按当前选中指标的时间区间汇总数值后降序选取 Top15；「区间汇总」中“收入”维度按“待结算金额”降序选取 Top15；“订单数”维度按“订单次数”降序选取 Top15。”三个统计子页面使用同一说明，每段说明独立换行。
- 查询栏中的图表按钮自身不带边框；按钮右侧保留小间距后放置独立的灰色竖向分隔线组件，再以小间距排列“周期明细／区间汇总”选择器。
- 图表按钮与左侧三级功能选择器之间使用更紧凑的间距；图标右侧与独立分隔线之间的既有间距保持不变，使图标两侧视觉均衡。
- 充值统计查询栏最左侧的三级功能选择器使用紧凑宽度 `178px`，仅缩小该选择器，不影响其他查询输入框。
- 三级功能使用自定义下拉列表，展开层与上方选择框使用相同 `178px` 宽度及相同左边界，左右边缘必须严格对齐；选项文字与选择框文字保持相同的 `10px` 左内边距。
- 查询栏“周期明细／区间汇总”和“按日／按月／按年”同样使用自定义下拉组件；展开层宽度、左右边界及文字内边距必须与各自选择框严格一致，不使用宽度不可控的浏览器原生下拉层。
- 充值明细“正式订单／测试订单”使用同一套自定义下拉规范，选择框与展开层均为 `198px`，左右边界和 `10px` 文字内边距严格对齐。
- 指定单个游戏或开发者后，展示当前实体在所选时间范围内的趋势折线图。
- 汇总统计的周期明细按当前筛选结果展示趋势折线图，区间汇总展示整体多金额指标堆叠柱。
- 周期明细的指标切换位于抽屉右上区域，可切换待结算金额、成功金额、失败金额、订单次数和订单人数；区间汇总右上角显示“收入／订单数”维度切换，并按所选维度展示对应分层柱状图。
- Top15 对象选择必须基于当前全部筛选条件和完整查询区间：周期明细按右上角当前选中指标在查询区间内的汇总值降序取前 15；区间汇总选择“收入”时按待结算金额降序取前 15，选择“订单数”时按订单次数降序取前 15。游戏统计的对象为游戏，开发者统计的对象为开发者；汇总统计仅有整体数据，不执行 Top15 选择。
- 区间汇总组合柱悬浮浮层不随当前命中的颜色区段只显示单项；悬浮到柱体任一区域时，必须一次列出该对象在当前查询区间内的全部柱状金额指标及对应金额，并使用与各分层一致的颜色标识。
- 区间汇总柱状图的金额图例支持选择和取消选择；取消某项后，所有对象对应的金额柱层同步隐藏，再次选择后恢复。悬浮浮层只列出当前已选中的金额项，纵轴按当前可见金额重新计算。
- 图表只改变呈现方式，不改变列表统计范围和指标口径。

## 11.1 PC 游戏充值明细

- 页面归属为“PC 游戏 / 充值明细”，只提供明细查询，不新增统计页面。
- 支付渠道表头支持漏斗筛选，选项为全部、微信PC扫码、支付宝PC扫码；列表 Mock 渠道值必须使用同一枚举。

- 列表字段为时间、订单号、游戏ID/名称、玩家ID/名称、订单状态、支付渠道、充值金额、平台补贴金额；查询总计只汇总充值金额和平台补贴金额。
- 订单号下钻字段为游戏ID/名称、订单号、游戏订单号、游戏币、游戏区服ID、服务端回传值。

- PC 游戏充值不进入快爆现有收入统计口径。
